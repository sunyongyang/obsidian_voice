# Note Listener / 笔记听读

Android 优先的 Obsidian 在线听读插件。当前为 **0.1.0 技术预览版，不是 SPEC 全量首版，也未通过安卓锁屏验收**。

无需电脑生成音频。安装及配置后，由手机按需请求在线语音，再在 Obsidian 内播放。当前仅接入用户自行配置的 **Microsoft Azure Speech**，可能产生账户费用；不包含免费 Edge TTS，不包含在线中转服务器，不包含手机本地模型。

## 当前可以测试什么

- 朗读当前 Markdown 笔记，随机抽取指定目录的笔记，本轮不重复。
- 开启随机连续播放，跨段和跨篇推进，候选耗尽后停止。
- 暂停、继续、停止、重试当前段、上一段、下一段和 0.75x 至 2x 倍速。
- 清理 Markdown、YAML、代码块、链接地址和嵌入，遵守 `tts: false` 及排除目录。
- 保存最近一篇的进度，正文变化后从头开始；有正在播放的会话时可以继续，应用重启后通过面板播放按钮恢复最近保存点。
- 一次只保留当前段及下一段预取音频，不把音频缓存写入仓库。
- 如果宿主暴露 Media Session，注册系统播放、暂停、停止及切换操作；接口存在不等于锁屏可用。

尚未实现：200 MB 持久缓存管理、日记日期筛选、手动配置日期格式、完整重试策略、播放端音频焦点与拔耳机的原生保证、逐句高亮、多引擎选择。锁屏控制、30 分钟锁屏跨段及跨篇、来电和耳机断开均未实机验收，不能声称已经满足通勤使用要求。

## 为什么暂时没有 Edge TTS

[edge-tts-universal 当前说明](https://www.npmjs.com/package/edge-tts-universal)指出，普通浏览器无法设置服务要求的 WebSocket 请求头，浏览器直连受限。Obsidian 手机插件不能把 Node.js/Python 版库直接当作本地依赖，也不能伪造浏览器允许范围之外的请求头。

因此此预览版提供正式 Azure 接口作为可选验证入口，不暗中新增中转服务。Azure 不是 Edge 的免费接口，最终后端选择仍待评审。用户未配置及授权时，不会调用服务。

## 构建

开发环境：Node.js 22 或更新版本及 npm。本项目在 Node.js 24 上构建。

```powershell
npm ci
npm test
npm run build
```

构建生成根目录的 main.js，以及 dist/note-listener 目录中的三个安装文件：

```text
note-listener/
  manifest.json
  main.js
  styles.css
```

开发时可运行 `npm run dev` 监听源码。编译完成不代表 Obsidian 已重载插件，需要禁用再启用。

## 安装到自己的 Obsidian

自己使用不需要向 Obsidian 网站“上传”。插件文件要放进你正在使用的笔记仓库的配置目录。

先使用测试仓库；不要一开始拿真实敏感日记做联网验证。

### Windows 安装

1. 找到 Obsidian 仓库的实际文件夹，不是 Obsidian 软件安装目录。
2. 关闭该仓库的 Obsidian 窗口。
3. 将整个 dist/note-listener 文件夹放到 `<仓库>/.obsidian/plugins/note-listener/`。如配置目录不是默认的 `.obsidian`，使用你实际的配置目录。
4. 确认该文件夹内直接包含上述三个文件，不要出现 `note-listener/note-listener/` 的重复嵌套。
5. 重新打开仓库，在“设置 → 第三方插件”启用第三方插件，再启用 **Note Listener**。
6. 在命令面板查找 **Note Listener: 打开听读面板**，或点击耳机图标。

### Android 安装

1. 将构建出的三个插件文件传到手机，或将提供的安装 ZIP 解压到手机。传输的是插件代码，不是预先生成的笔记音频。
2. 在手机文件管理器打开实际的 Obsidian 仓库文件夹，开启“显示隐藏文件”。
3. 关闭 Obsidian，把文件放进 `<手机仓库>/.obsidian/plugins/note-listener/`，路径结构与 Windows 相同。不要放进 Android 应用私有数据目录，也不要放到仓库根目录的普通笔记文件夹。
4. 重新打开 Obsidian，在“设置 → 第三方插件”中启用 **Note Listener**。
5. 通过命令面板启动；也可在 Obsidian 的移动工具栏设置中添加“朗读当前笔记”和“打开听读面板”命令，具体菜单位置随应用版本变化。

如果手机文件管理器看不到隐藏目录，可通过 USB 文件传输或支持隐藏目录的文件管理器操作。不需要 root。Obsidian Sync 若启用相应插件同步选项，也可用来传输插件代码，但必须确认手机已收到三个文件且单独启用了插件，不假定所有同步工具都会同步 `.obsidian`。

### 更新与卸载

- 更新前停止播放、禁用插件，再替换三个安装文件并重新启用。不要把桌面的 data.json 一起复制到手机。
- 卸载通过第三方插件设置完成；它会结束插件音频。此预览版没有外置音频目录。
- 没有安装到任何真实仓库，也没有修改你的 Obsidian 配置。本仓库只生成了安装产物。

## 配置与首次朗读

1. 在 Azure 创建 Speech 资源，确认计费方案、地区和适用额度。你需要的是 Speech 资源的密钥，不是 OpenAI API Key；不确定计费前不要授权真实日记。
2. 打开 Note Listener 设置，填写与资源一致的区域，例如 `eastasia`，选择中文音色。此预览版使用区域端点，要求资源支持该鉴权方式。
3. 随机听读目录每行一个，例如 `日记`、`知识/复习`；路径相对当前仓库。空列表表示不启用随机范围，`/` 显式表示全库。排除目录同样每行一个，例如 `日记/私密`。
4. 点击“输入密钥并授权”，**在插件内**填写密钥，勾选明确的云端发送与费用授权。不要把密钥发到聊天或写入笔记。
5. 打开听读面板，先点“试听”。测试文本是固定示例，试听结束不会自动转入随机日记。
6. 再打开一篇测试笔记，点击“朗读当前笔记”；或配置好范围后点击随机按钮。

密钥和授权仅存内存，Obsidian 重启、禁用或卸载插件后均需重新输入。更改 Azure 区域会撤回旧授权并清除内存凭据。密钥不会写入 data.json；该文件只保存普通设置及最近播放进度。

预览版为了保持单一播放会话，更改范围、音色或区域会停止当前播放并清除旧进度；这与 SPEC 中“音色下一篇生效”的最终交互不同。

## 隐私与网络

- 用户授权后，当前笔记标题、清理后的正文片段及下一段预取文本会发送到 `https://<region>.tts.speech.microsoft.com`。不上传全库，不使用其他接收服务，不静默切换引擎。
- 音频只在内存中保存当前段和下一段；停止、切篇、撤权或卸载时释放其引用及对象 URL。不保证操作系统或宿主内部不会缓存网络数据。
- 最近播放进度包含笔记路径和内容哈希，保存在插件的 data.json，可能被仓库同步软件同步。可在设置中“清除进度与音频”。
- 用 `tts: false` 禁止指定笔记被朗读。笔记删除、重命名或变成禁止听读时，终止相关会话并清除进度。
- 无客户端遥测，不记录正文或密钥到日志，不访问仓库外文件，不需要麦克风权限。
- Obsidian 的 requestUrl 没有提供可取消接口：停止会立即停止本地播放、取消等待、丢弃迟到的结果，但已经发往 Azure 的请求可能继续完成并产生费用。预览版不会自动重试，避免重复计费。

```yaml
---
tts: false
---
```

## 安卓真机验收

当前没有真机或真实 Azure 在线合成测试证据。源码测试使用模拟网络及音频对象，只验证逻辑，不证明音质、后台能力或 Obsidian 宿主行为。

在目标手机按以下顺序验证，记录手机型号、Android、Obsidian、Android System WebView 版本及电池策略：

1. 用固定文本试听，确认不是只通过构建，确实能收到并播放在线音频。
2. 打开足够长的测试笔记，前台播放后锁屏，听 30 分钟，期间需要多次新分段合成。
3. 在随机目录放至少三篇足够长的测试笔记，开启连续播放，锁屏验证跨篇自动合成和播放。
4. 测试锁屏暂停、继续、切换到其他应用、断网恢复、来电和蓝牙耳机断开。测试断开时先调低扬声器音量，不能预设宿主一定会暂停。
5. 在“输入密钥并授权”以外不提供任何真实敏感笔记，首次实验失败时用虚构测试笔记复现。

若第一步失败，先核对 Azure 区域、资源权限、网络和密钥。若系统媒体接口不可用、锁屏后停播、不能跨篇，记录现象并暂停完整产品开发；不能靠屏幕常亮或电脑预生成来宣称需求完成。原生辅助方案需要另行评审。

## 公开发布到社区目录

本地安装不等于已上架。当前预览版未提交、未发布，也不建议在锁屏及隐私验收前当作完整产品推广。

准备公开发行时：

1. 在自己的 GitHub 仓库公开可审阅源码，准备本说明、合适的许可证及联网/费用披露。当前尚未选择发行许可证。
2. 验证最低支持的 Obsidian 版本；清单中 `1.5.0` 目前是 API 目标，不是实测兼容认证。
3. 将清单和包版本同步更新，发布同版本 GitHub Release，例如 `0.1.0`，不加 `v` 前缀。
4. 给 Release 单独上传 main.js、manifest.json 和 styles.css，不只上传源码 ZIP 或整个安装 ZIP。
5. 按[官方当前提交流程](https://docs.obsidian.md/plugins/releasing/submit-plugin)登录 [Community directory](https://community.obsidian.md/)，关联 GitHub 并提交插件，处理审核反馈。不要照旧教程向发布仓库提交 PR。
